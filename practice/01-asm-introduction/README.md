Нужни са `nasm`, `ld` и `objdump` (от binutils), `make` и `gdb`. По желание -

## 1. Основи: от схемата на процесора до асемблер

### Процесорът от схемата

Минаваме през кадрите на схемата един по един:

1. **RAM** - всяка клетка има *адрес* и *данни* (8 бита). Входове: адрес
   (ADDRESS INPUT), данни (DATA), разрешение за четене (READ ENABLE) и за
   запис (WRITE ENABLE).
2. **Регистри A, B, C, D** - по 8 бита, в самия процесор. Най-бързата памет
   (вж. „Скорост и обем по нива“ от презентация 01).
3. **Инструкции** - всяка е 8 бита: 4-битов *код на операцията* (на англ.
   opcode) и 4 бита *операнд* - адрес в RAM или два 2-битови номера на
   регистри.

   | Инструкция | Опкод  | Операнд                | Действие          |
   | ---------- | ------ | ---------------------- | ----------------- |
   | `LOAD_A`   | `0010` | адрес                  | A = RAM[адрес]    |
   | `LOAD_B`   | `0001` | адрес                  | B = RAM[адрес]    |
   | `STORE_A`  | `0100` | адрес                  | RAM[адрес] = A    |
   | `ADD`      | `1000` | регистър, регистър     | втори = първи + втори |

4. **Регистър на инструкцията** (IR) - текущата инструкция, и **регистър на
   адреса на инструкцията** (IAR) - откъде да вземем следващата.
5. **Управляващо устройство** (CU) - изпълнява безкрайно цикъла *извличане*
   (fetch) → *декодиране* (decode) → *изпълнение* (execute), след което
   увеличава IAR с 1.
6. **ALU** - смята. Освен резултата дава и *флагове*: O (препълване), Z (нула),
   N (отрицателно).

**Упражнение.** Декодирайте програмата в адреси 0-3. Какво ще има в адрес 13,
след като се изпълни?

| Адрес | Данни       |
| ----- | ----------- |
| 0     | `0010 1110` |
| 1     | `0001 1111` |
| 2     | `1000 0100` |
| 3     | `0100 1101` |
| 14    | `0000 0011` |
| 15    | `0000 1110` |

### Какво е асемблер?

- В паметта инструкциите са просто байтове - *машинен код*. За процесора
  `0010 1110` е `LOAD_A 14`, за нас - само число.
- *Асемблерният език* е текстов запис на машинния код: всяка инструкция има
  име (мнемоника) - `LOAD_A`, `mov`, `add` - и операнди. Почти всеки ред
  отговаря на точно една машинна инструкция.
- *Асемблерът* (на англ. assembler) е програмата, която превежда текста в
  машинен код. Ние ще използваме NASM. На български и езикът, и програмата се
  наричат „асемблер“.
- Всяка архитектура има свой език - x86-64, ARM64, RISC-V се различават.

От текст до изпълним файл:

```text
rep7.asm  --nasm-->  rep7.o  --ld-->  rep7
 (текст)        (обектен файл)    (изпълним файл)
```

Същото прави и `gcc` - само че първо превежда C до асемблер. Можете да го видите
с `gcc -S -masm=intel main.c` (резултатът е в `main.s`).

### Структура на файл за NASM

```nasm
section .data                   ; данни - низове, числа
    msg db "Hi", 10             ; db - байтове; dw - 2, dd - 4, dq - 8 байта
    len equ $ - msg             ; константа, смята я асемблерът

section .text                   ; код
    global _start               ; ld трябва да вижда _start

_start:                         ; етикет - име на адрес; оттук започва програмата
    mov rax, 60                 ; коментарите са след ;
```

### Пример 01 - [01-exit.asm](./examples/01-exit.asm)

Изграждаме го на ръка, без Makefile:

```bash
nasm -f elf64 01-exit.asm -o 01-exit.o
ld 01-exit.o -o 01-exit
./01-exit
echo $?
```

Трите реда с `syscall` засега приемаме наготово - обясняваме ги в т. 4.

**Опит.** Изтрийте реда със `syscall`. Програмата завършва със `Segmentation
fault` (изходен код 139 = 128 + 11, сигнал SIGSEGV). Както процесорът от схемата,
и истинският продължава с байтовете след програмата - докато ядрото не го спре.

## 2. Регистри

| Схемата                          | x86-64                                         |
| -------------------------------- | ---------------------------------------------- |
| регистри A-D, по 8 бита          | 16 регистъра с общо предназначение, по 64 бита |
| IAR                              | `rip`                                          |
| IR                               | има го, но програмите не го виждат             |
| флагове O, Z, N                  | `OF`, `ZF`, `SF` (и `CF` за пренос) в `rflags` |
| `LOAD_A 14`                      | `mov rax, [x]`                                 |
| `STORE_A 13`                     | `mov [result], rax`                            |
| `ADD B, A` (резултатът - във втория) | `add rax, rbx` (резултатът - в първия)     |
| всяка инструкция е 1 байт        | инструкциите са от 1 до 15 байта               |

Регистрите с общо предназначение и имената на частите им:

| 64 бита     | младши 32   | младши 16   | младши 8    |
| ----------- | ----------- | ----------- | ----------- |
| `rax`       | `eax`       | `ax`        | `al` (`ah`) |
| `rbx`       | `ebx`       | `bx`        | `bl` (`bh`) |
| `rcx`       | `ecx`       | `cx`        | `cl` (`ch`) |
| `rdx`       | `edx`       | `dx`        | `dl` (`dh`) |
| `rsi`       | `esi`       | `si`        | `sil`       |
| `rdi`       | `edi`       | `di`        | `dil`       |
| `rbp`       | `ebp`       | `bp`        | `bpl`       |
| `rsp`       | `esp`       | `sp`        | `spl`       |
| `r8`-`r15`  | `r8d`-`r15d`| `r8w`-`r15w`| `r8b`-`r15b`|

- `ah`, `bh`, `ch`, `dh` са битове 8-15 - наследство от 16-битовия 8086.
- `rsp` сочи върха на стека - не го използваме за други неща (`call` и `ret`
  разчитат на него).
- `rip` не може да се запише с `mov` - сменя се само с преходи.
- `[x]` е стойността на адрес `x`, а `x` - самият адрес. Като `*p` и `p` в C.
  В задачата `mov rsi, message` слага в `rsi` *адреса* на низа.

### Пример 03 - [03-registers.asm](./examples/03-registers.asm)

Разглеждаме я в `gdb` инструкция по инструкция (`stepi`, `p/x $rax`):

- `al`, `ah`, `ax` сменят само своята част от `rax`, а записът в `eax` нулира
  горните 32 бита.
- `x/8xb &value` показва байтовете `88 77 66 ... 11` - little-endian, както в

  километража от презентация 01.

## 3. Makefile - припомняне

До тук написахме `nasm ...` и `ld ...` поне три пъти. `make` го прави вместо нас
и изгражда отново само това, което се е променило (сравнява времената на
промяна на файловете).

```make
# цел: зависимости
# <TAB>команда
rep7: rep7.o
	ld rep7.o -o rep7

rep7.o: rep7.asm
	nasm -f elf64 rep7.asm -o rep7.o

.PHONY: clean                   # clean не е файл
clean:
	rm -f rep7 rep7.o
```

- `make` без аргументи изгражда първата цел, `make clean` - посочената.
- Ако командата започва с интервали вместо TAB: `missing separator`.
- В [examples/Makefile](./examples/Makefile) същото е с променливи и общи
  правила (на англ. pattern rules): `%.o: %.asm` важи за всеки `.asm` файл, `$<`
  е зависимостта, а `$@` - целта.

**Опит.** Изпълнете `make` два пъти - вторият път няма какво да прави. После
`touch 04-hello.asm` и `make` - изгражда отново само `04-hello`.

## 4. Системни извиквания

От презентация 02: програмата работи в потребителски режим и не може сама да
пише по екрана или в файл. Иска това от ядрото чрез системно извикване - казва
само *номера* му, а ядрото го търси в таблица. В C `write()` е обвивка от `libc`,
която прави точно това. На асемблер го правим сами:

| Какво             | Къде                                                |
| ----------------- | --------------------------------------------------- |
| номер             | `rax`                                               |
| аргументи 1-6     | `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`              |
| извикване         | инструкцията `syscall`                              |
| резултат          | `rax` (при грешка - отрицателен код, `-errno`)      |
| губят стойността си | `rcx` и `r11` (`syscall` ги използва)             |

| Извикване | Номер | Аргументи                        |
| --------- | ----- | -------------------------------- |
| `read`    | 0     | fd, адрес на буфер, брой байтове |
| `write`   | 1     | fd, адрес на буфер, брой байтове |
| `open`    | 2     | път, флагове, права              |
| `close`   | 3     | fd                               |
| `exit`    | 60    | изходен код                      |

Откъде да ги намерим:

- `man 2 syscall` - таблицата с регистрите за всяка архитектура;
- `man 2 write` - аргументите на конкретно извикване;
- `/usr/include/asm/unistd_64.h` (в Debian и Ubuntu -
  `/usr/include/x86_64-linux-gnu/asm/unistd_64.h`) - номерата;
- <https://filippo.io/linux-syscall-table/>.

### Пример 04 - [04-hello.asm](./examples/04-hello.asm)

`write(1, msg, len)` и после `exit` с върнатото от `write` - `echo $?` дава 14.

- **Опит.** Сменете файловия дескриптор на 42. Изходният код е 247. `write`
  връща -9 (`EBADF`, `man 3 errno`), а -9 като байт без знак е 256 - 9 = 247 -
  допълнителен код, като `(unsigned char)-1 == 255`.
- **Опит.** `strace ./04-hello` показва само `execve`, `write` и `exit`.
  Сравнете със `strace` на „Hello, world!“ на C - там преди `write` има десетки
  извиквания, с които се зарежда `libc`.

## 5. Инструкции: сравнение, преход, подпрограма

`objdump -d -M intel 02-toy-cpu` показва машинния код до всяка инструкция.
Забележете, че `mov rax, 60` е станало `mov eax, 0x3c` - 5 байта вместо 10, със
същия ефект. Защо? (вж. пример 03)

> NASM използва синтаксиса на Intel: `mov цел, източник`. `gdb` и `objdump` по
> подразбиране показват синтаксиса на AT&T, където редът е обратен
> (`mov $60, %rax`). Затова `-M intel` за `objdump` и
> `set disassembly-flavor intel` за `gdb`.

| Инструкция     | Действие                                  | На C              |
| -------------- | ----------------------------------------- | ----------------- |
| `mov a, b`     | a = b                                     | `a = b;`          |
| `add a, b`     | a = a + b                                 | `a += b;`         |
| `sub a, b`     | a = a - b                                 | `a -= b;`         |
| `inc a`        | a = a + 1                                 | `a++;`            |
| `dec a`        | a = a - 1                                 | `a--;`            |
| `cmp a, b`     | смята a - b и пази само флаговете         |                   |
| `jmp L`        | преход към L                              | `goto L;`         |
| `je L` / `jz L`  | преход, ако `ZF = 1` (равни)            | `if (a == b) goto L;` |
| `jne L` / `jnz L`| преход, ако `ZF = 0` (различни)         | `if (a != b) goto L;` |
| `call L`       | запомня адреса за връщане в стека и прескача към L | извикване на функция |
| `ret`          | взима адреса от стека и продължава оттам  | `return;`         |
| `syscall`      | системно извикване                        |                   |

- Флаговете са тези от ALU в схемата. `cmp` е `sub`, който не записва
  резултата.
- `je` и `jz` са една и съща инструкция с две имена (същото за `jne` и `jnz`) -
  „равни“ значи „разликата е нула“.
- Цикъл на асемблер е етикет и условен преход назад - като `do { ... } while`
  в C.
